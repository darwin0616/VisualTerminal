## 要 inkling 做什麼

連線後的「拼塊工作區」：使用者不用打指令，點選拼塊組出管線（例如「容器日誌 → 搜尋 error → 計算行數」），執行後在下方看到像終端機的輸出紀錄。同時修正上一階段的三個介面問題。

### 1. 修正階段 01 的問題
| # | 問題 | 要求 |
|---|---|---|
| A | 中文輸入法打出全形字 | 寫 `toHalfWidth`，主機、帳號、Port 使用前先把全形 ASCII（U+FF01～FF5E）與全形空白轉成半形 |
| B | Port 顯示成「2,222」 | 顯示 port 一律用 `String(port)` 或 `Text(verbatim:)` |
| C | 結束碼顯示成「Optional(0)」 | 新的輸出紀錄正確顯示結束碼 |

### 2. 十種拼塊與指令組裝（`Blocks.swift`，只能用 Foundation）
| 類別 | 拼塊 | 組出的指令 |
|---|---|---|
| 資料來源 | 容器清單 | `docker ps [-a] --format '<被選欄位的 template，用 \t 連接>'` |
| | 容器日誌 | `docker logs --tail N <容器> 2>&1`（`2>&1` 讓錯誤訊息也能被搜尋） |
| | 讀取檔案 | `cat <路徑>`；`~/` 開頭時保留 `~/` 讓遠端展開 |
| 過濾與處理 | 搜尋 | `grep [-i] [-v] (-E 或 -F) -- <文字>` |
| | 取代 | `sed 's/<跳脫後的文字>/<跳脫後的取代>/g'` |
| | 前幾行／後幾行 | `head -n N`／`tail -n N` |
| | 計算行數、排序、去除重複 | `wc -l`、`sort [-r] [-n]`、`sort -u` |

- 使用者輸入一律經過 `ShellQuote.quote`；參數不完整時回傳 nil（例如沒選容器）。
- 整條管線：第一塊必須是資料來源、其餘不是，才用 ` | ` 連接。

### 3. 工作區模型（`WorkspaceModel.swift`）
拼塊的新增（資料來源取代第一塊）、刪除、上下移動；讀取伺服器上的容器名稱；執行（即時接收輸出）、停止（取消執行）、輸出超過 20 萬字截斷；清除紀錄。

### 4. 畫面
- 左：拼塊庫（兩個分類，點一下加入）。
- 右上：管線編輯（每塊一張卡片、參數控制項、上移／下移／刪除、卡片之間的箭頭），下方「指令預覽」與「執行／停止」（⌘↩）。
- 右下：像終端機的輸出紀錄（`$ 指令`、輸出、結束碼／已停止、自動捲動、清除紀錄）。

### 工具與環境問題（不是 inkling 的錯）

1. **Claude 的開發腳本誤抽程式碼片段**：inkling 在說明文字中附了 5 段沒有檔名的程式碼片段（例如單獨一個 `Toggle(...)`），腳本把它們當成 `File10.swift`～`File14.swift` 加進專案，造成 2 個編譯錯誤（[`errors_r0-extraction.txt`](runs/02-docker-blocks/errors_r0-extraction.txt)）。
2. **Ollama 在修正輪因 GPU 記憶體不足而當掉**：修正輪會把需求、inkling 整段 44 KB 的回覆與錯誤一起再送一次，上下文太大，加上模型本身約 22 GB，Mac（32 GB）的 GPU 記憶體不足：`mlx: [METAL] Command buffer execution failed: Insufficient Memory`（[`ollama-oom.log`](runs/02-docker-blocks/ollama-oom.log)）。
3. **腳本當掉時沒有還原原始碼**：第 1 次失敗留下的檔案，被第 2、3 次當成「目前專案的檔案」帶入，所以那兩次不採計。

**已修正的腳本**（[`tools/ai_dev.py`](../tools/ai_dev.py)）：只抽取標有 `// File:` 的程式碼區塊；呼叫模型失敗時一定還原原始碼；修正輪只帶出錯的檔案與錯誤訊息，不再附上整段舊回覆。

### 改為手動驗證 inkling 第一輪的輸出

把第 1 次（seed 42）第 0 輪的輸出放進專案、**只去掉那 5 個誤抽的片段檔案**，結果：

- **一次編譯成功**（`BUILD SUCCEEDED`），沒有任何編譯錯誤。
- 新增 6 個檔案、共 657 行（整個 app 911 行）。

> inkling 的回覆有兩個小瑕疵：說明中夾了 5 段無檔名的程式碼片段，以及 3 個檔案（WorkspaceView、BlockPaletteView、PipelineEditorView）在同一則回覆中輸出了兩次（後面的版本覆蓋前面的）。system prompt 有要求「程式碼輸出一次就結束」，它沒有完全遵守，也讓這一輪多花了時間。

| 指標 | 結果 |
|---|---|
| 編譯 | inkling 的程式**一次編譯成功**（失敗都來自工具誤抽片段） |
| 功能 | 邏輯 **51/51**，含注入防護、sed 跳脫、stderr 合併、停止與截斷；畫面漏做「中斷連線」 |
| 功能回饋 | 0 次 |
| 需求遵守 | 指令組裝規則逐字正確；三個舊問題都照要求修正；**漏做 1 項**（工具列的連線資訊與中斷連線） |
| 瑕疵 | 回覆中夾帶無檔名片段、3 個檔案重複輸出 |
| 時間 | 第 0 輪約 19 分鐘（輸出 44 KB）；大型需求單輪很慢 |
| 環境限制 | 32 GB Mac 跑 inkling 時，上下文一大就 GPU 記憶體不足；大型階段應拆小，修正輪只帶必要內容 |

這一階段 inkling 的程式品質仍然很高；真正的瓶頸是速度與記憶體，以及開發工具本身要更穩健。
