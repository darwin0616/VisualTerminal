# inkling 開發能力評測

VisualTerminal 的介面由本地模型 **inkling-2-mini** 撰寫，Claude（Claude Code）負責寫需求與驗證。這個資料夾記錄每一個開發階段：

- **要 inkling 做什麼**：給它的完整需求（原文）。
- **測試了什麼**：怎麼驗證它寫的程式、結果如何。
- **真實紀錄**：每一輪的耗時、token、編譯錯誤原文、原始回覆（`runs/`）。

## 分工

| 部分 | 誰寫 | 原因 |
|---|---|---|
| SSH 核心（SwiftNIO SSH）、`ShellQuote` 引號處理 | Claude | 牽涉密碼、伺服器指紋與遠端指令注入，且 SwiftNIO SSH 的 API 冷門 |
| 畫面、拼塊、指令組裝、輸出紀錄 | **inkling** | 評測對象 |
| 需求、編譯回饋、功能驗證、程式碼審查 | Claude | |

inkling 不需要自己實作 SSH：system prompt（[`prompts/macos-v1.txt`](../prompts/macos-v1.txt)）附有 SSH 核心的 API 說明。

## 每一階段的流程

1. **需求**：Claude 寫 `steps/NN-*.md`，只描述功能、檔案分工與介面行為，不提供實作程式碼。
2. **開發迴圈**（[`tools/ai_dev.py`](../tools/ai_dev.py)）：
   - 把需求 + 目前所有原始碼交給 inkling。
   - 抽出它輸出的 Swift 檔案，用 `xcodebuild` 編譯（Swift 6 語言模式、嚴格並行檢查）。
   - 編譯失敗：把錯誤訊息（含出錯的那一行）回饋給它修正，最多 5 輪。
   - 「型別轉換一定失敗」「方法簽名幾乎吻合但不會被呼叫」這類警告視同錯誤。
3. **程式碼審查**：Claude 逐行讀過，對照需求逐項檢查。
4. **功能驗證**：編譯成功不代表能用。把 inkling 寫的邏輯接上**真實的 SSH 測試伺服器**（[`testserver/`](../testserver/)）實際執行，逐項檢查結果。
5. **實機操作**：用 XCUITest 實際操作 app 並截圖，找出只有點畫面才看得到的問題（輸入法、顯示格式…）。
6. **回饋**：功能有錯時，Claude 描述問題（不給答案）讓 inkling 修正，並記錄回饋次數與內容。

## 評分項目

| 指標 | 意義 |
|---|---|
| 編譯輪數 | 第一次就編譯成功，或修了幾輪；錯誤屬於哪一類 |
| 功能正確 | 實測項目通過幾項（第一版、回饋後） |
| 功能回饋次數 | 編譯成功後，Claude 還需要回饋幾次才能用 |
| 需求遵守 | 需求列的細節做到幾項、漏了或做錯哪些 |
| 程式品質 | 有沒有空的事件處理、用 `Any` 規避型別、多做需求外的東西 |
| 時間 | 每一輪與總共花多久 |

## 對照組：gemma4:12b

同一套流程之前用 **gemma4:12b** 開發 iPhone app（另一個專案 iPhoneToolKits）。gemma 第一版登入畫面雖然編譯成功，卻完全無法登入（2 個致命錯誤），前後回饋 4 次才可用，最後的回饋得寫到接近答案。
